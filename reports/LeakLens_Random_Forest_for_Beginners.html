0Where the forest fits

The random forest answers one question: what kind of event is this?

Saved data for a scenario→14 numbers→Quiet check→Random forest→Verdict + confidence→(if leak) rank nodes
  • Input: 14 numbers that summarise a whole scenario (for example, “how much water vanishes at the worst node?”).
  • Output: a probability for each of 7 kinds: normal day, leak, demand change, pump/reservoir, tank change, blocked pipe, pipe ageing.
  • It is the only “learned” step. The noise levels, the unaccounted-flow calculation and the node ranking are calculations, not learning.
ImportantThe forest does not find where a leak is. It only names the kind of event. The location comes from a separate formula (score = A + 0.3·D).

This page uses the project’s real, trained forest. Its numbers (tree counts, depths, votes) were read from the saved model.

1What is a decision tree?

A decision tree is a list of yes/no questions that ends in an answer.

Like the game “20 questions”: each answer sends you down a different branch until you reach an end-point. Here is the top of a real tree from our forest (tree #1):

unacc_ratio ≤ 1.21 ?
   yes: flow_frac ≤ 0.04 ?
   yes:    yes: → normal …(tree continues)
   yes:    no:  → demand_change …(tree continues)
   no:  tank_change ≤ 0.02 ?
   no:     yes: → valve_block …(tree continues)
   no:     no:  → leak

Reading it: “Is unacc_ratio (water vanishing at one node, in noise units) at most 1.21? If no, ask the next question…”. The tree ends in answers such as leak.

A beginner’s pictureImagine a doctor’s checklist: “fever? → yes → cough? → no → …”. Each question splits the patients into groups that are more alike. A tree is built so each split makes the groups as pure as possible, for example all “leaks” on one side.

3Why one tree is not enough

A single tree can memorise its training data, and then stumble on new data.

If you let one tree grow until every training row is classified perfectly, it learns the quirks of those rows, not just the pattern. We tried it on our data:

One decision treeOn training rowsOn unseen test rows
Grown fully (depth 15, 51 end-points)100.0% (perfect: memorised)82.0%
Kept short (depth 4, for readability)—69.1%

The idea of a forest: build many different trees, so their individual quirks differ, and let them vote. Quirks cancel; the real pattern stays. This is “the wisdom of the crowd”.

4How exactly are the 300 trees different?

Same recipe, but each tree sees different rows and asks different questions. There are two sources of randomness, and both are real settings in this project.

Difference 1: each tree gets its own sample of the rows

This is called bootstrap sampling. For each tree, the computer draws 478 rows with replacement: it picks a row at random, notes it, puts it back, and picks again, 478 times. Result: some rows are picked several times, and some are never picked.

Try it. Twelve toy scenarios, A to L. Press the button to give a tree its own sample:

Cards drawn twice or more show a badge. Faded cards were left out: this tree never sees them.

Real numbers from our forestEach tree draws 478 rows, but ends up using only about 54% of the distinct rows (between 49% and 58% depending on the tree); the rest are repeated. The left-out rows are called out-of-bag.
A twist in our version: balanced samplingWe set class_weight="balanced" because leaks are 48.5% of the rows. In the scikit-learn version used here, this also changes the drawing: every tree’s sample contains about 14.3% of each of the 7 kinds (7 kinds × 14.3% = 100%), instead of 48.5% leaks. So rare kinds such as “pipe ageing” (6% of the rows) are drawn more often and repeated, and leaks are drawn less often. This stops the forest from simply favouring “leak”. (We measured this on the saved model.)

Difference 2: each question only considers a few random numbers

When a tree needs to pick its next question, it does not look at all 14 numbers. It looks at a random subset of 3 (that is √14, rounded down) and picks the best question among those. A new random subset is drawn at every question.

Try it. The 14 numbers; press the button to see which 3 a tree may use for its next question:

question 1

Because of this, even trees given the same rows would ask different questions. It stops every tree from always using the one strongest number first.

5How a single tree is grown

A tree is built from the top, one best question at a time.

  1. Start with all the rows given to this tree (its bootstrap sample), mixed together.
  2. Consider the 3 randomly allowed numbers. For each, try possible cut-off values (for example unacc_ratio ≤ 1.21).
  3. Pick the question that makes the two groups purest, meaning each group contains mostly one kind. Purity is measured by gini: 0 for a perfectly pure group, higher when kinds are mixed.
  4. Split the rows into “yes” and “no”, and repeat steps 2–3 on each group with a fresh random choice of 3 numbers.
  5. Stop when a group is pure (all one kind) or cannot be split. Each end-point answers with the kind of the rows that reached it.
gini = 1 − Σ (share of each kind)²Example: a group with 9 leaks and 1 normal: 1 − (0.9² + 0.1²) = 0.18 (nearly pure). 5 leaks and 5 normal: 0.5 (very mixed).

No depth limit is set, so trees keep growing until the groups are pure. That is why single trees memorise (step 3); the voting in step 6 fixes it.

6The forest votes

For a new scenario, all 300 trees answer, and the answers are combined.

Follow one real tree for the leak at node 15 (an unseen test scenario). Its numbers: unacc_ratio ≈ 10 and tank_change ≈ 0.03:

  1. Is unacc_ratio ≤ 1.21? This scenario has 9.99, so the answer is no.
  2. Is tank_change ≤ 0.02? This scenario has 0.03, so the answer is no.
  3. End-point reached: the tree answers Leak.

That is one tree’s vote: Leak. Now all 300 trees do the same. Each square is a tree, coloured by its answer (hover for details):

A small technical detail

Strictly, scikit-learn does not count hard votes. Each tree reports the share of each kind in the end-point it reached, and the forest averages these shares over the 300 trees. Because our trees are grown until their end-points are pure, each tree’s share is almost always 100% for one kind, so the average is effectively the vote share.

7From votes to the verdict you see

  1. Probabilities: the forest gives one number per kind, adding to 100%.
  2. Verdict: the kind with the highest probability.
  3. Confidence label on the dashboard: High if the top probability is 85% or more, Medium from 60%, otherwise Low. It is a vote share, not a guaranteed accuracy.
  4. Quiet check can override: before this, if all 14 signals were within noise, the answer was already set to “Normal day” and the forest’s answer is replaced.
  5. If the verdict is leak, the separate node ranking runs. Otherwise the dashboard shows the kind of event and the reasons.

8Does the forest really help? Real numbers

Individually, the trees are weaker than the whole forest. Voting lifts the result.

We scored each of the 300 trees on the 139 unseen test scenarios:

Be honest about thisThe forest beats the average single tree by about 9 points and the short tree by a lot, but only by about 2 points over one fully grown tree (82.0%). With only 139 test scenarios, that small gap is within the noise: we cannot claim the forest is clearly better than a single full tree here. The forest’s advantage is that its answers are steadier and it gives a vote share you can use as a confidence. The whole-system number is slightly lower than the forest alone because the quiet check sometimes calls small events “normal”.

10Which of the 14 numbers matter most?

A forest can report how much it relies on each number. For every question in every tree it records how much the question made the groups purer, adds it up per number, and averages over the 300 trees.

The unaccounted-flow numbers and the demand-evidence numbers are near the top, which makes sense: they separate leaks from demand changes. But the importance is fairly evenly spread, so no single number does everything. Note importance means “used a lot”, not “causes the event”.

11Train, save, use, test: end to end in the project

  1. Build the table. train.py computes the 14 numbers for every scenario and saves features.csv (one row per scenario, with a train/test tag).
  2. Train. Only the 478 training rows go into RandomForestClassifier(n_estimators=300, class_weight="balanced", random_state=0). A depth-4 tree is trained alongside, only so its rules can be read.
  3. Save. The trained forest is saved to a file (with joblib). Its readable tree rules go to decision_rules.txt.
  4. Use. When someone presses Analyse, the backend loads the saved forest once, builds the 14 numbers for that scenario, calls predict_proba, and gets the 7 probabilities (step 6–7).
  5. Test. evaluate.py runs the forest on the 139 test rows it never saw and records accuracy, precision, recall, F1 and the confusion matrix. Those test numbers are the ones we report.
Two accuracy numbers, do not mix themOn the training rows the system scores 95.6% (it has seen them); on the unseen test rows 82.7%. Quote the test number.

12Honest notes

  • No tuning. Number of trees, depth limit and other settings were not optimised.
  • Small data. 478 training rows and 139 test rows: results have wide margins of error, and the split was made once.
  • Out-of-bag check is optimistic. A forest can score itself on each tree’s left-out rows. We measured 96.9% that way, but it is higher than the test result because near-copies of a scenario (the same leak node at other sizes, noisy twins) sit in other trees’ samples. That is why we trust only the held-out test.
  • Hard cases. Pump, tank, blockage and ageing are sometimes confused with each other; small events can look normal.
  • Single tree is close. On this small test, one fully grown tree is nearly as accurate as the forest (step 8).
  • Confidence is not calibrated. 94% means 94% of trees agreed, not “right 94% of the time”.

13Self-check

What does the random forest decide, and what does it not decide?
It decides the kind of event (7 kinds). It does not decide where a leak is: that is the separate score A + 0.3·D.
In what two ways do the 300 trees differ?
(1) Each is trained on its own bootstrap sample of the training rows (drawn with replacement, balanced by kind). (2) At each question it may only use a random subset of 3 of the 14 numbers. This makes their depth, questions and end-points differ.
What is bootstrap sampling?
Drawing rows at random with replacement until you have as many as the original. Some rows repeat, about half are never picked (here about 54% of distinct rows are used).
Why only 3 numbers per question?
So trees do not all copy the single strongest number; it makes them less alike, and voting works best when the voters are different. 3 = √14 rounded down.
How does the forest turn 300 answers into one verdict?
It averages the trees’ answers into a probability per kind (effectively the vote share) and picks the highest. The top probability is the confidence.
Is the forest’s advantage over a single tree large here?
No. Against the average tree in the forest it is about 9 points; against one fully grown tree it is about 2 points, which is within the noise of 139 test scenarios.
What was it trained on, and what tested?
Trained on one row of 14 numbers for each of the 478 training scenarios; tested on the 139 unseen test scenarios.
Why is the result the same every time we re-train?
The randomness uses a fixed seed (random_state=0), so the same rows give the same forest.
RememberAll data are simulated. The forest was not tuned, and the test set is small.
